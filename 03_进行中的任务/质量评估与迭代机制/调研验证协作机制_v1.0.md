# 调研验证协作机制 v1.0

> 文档类型：Governance（治理规范）｜ 更新频率：机制变更时 ｜ 维护者：AI 自动维护+用户审核 ｜ 读者：AI 代理
> 创建：2026-10-06 ｜ 动因：**LibTV 复核教训**——调研曾仅凭 GitHub README 单一来源定论"libtv 仅会话式桥接 4 端点"，错漏官方 2026-08-31 已升级 LibTV CLI 1.1.3（画布/节点级统一入口）、以及 LiblibAI 星流 API 平台，用户质疑后当场复核才纠正。
> 原则：**调研必须多查多看；结论必须过交叉验证；单源不得定论。**

## 1. 适用范围

- 一切多智能体调研（工具/平台/方法论/案例/价格/门槛结论）
- 单源小查证同样适用证据等级规则（§2），只是不强制派验证 Agent

## 2. 证据等级（升级门槛，覆盖原四档）

| 等级 | 定义 | 硬门槛 |
|---|---|---|
| ✅ 已查证 | 官方一手来源 | **必须官方原文**（公告/文档/产品页/服务条款/官方仓库），URL 可直接回源复现 |
| 🔶 经搜索补充 | ≥2 独立来源互证 | **至少 2 个相互独立来源**（非同源转载链），口径一致 |
| 🟡 博主一方说法 | 单一博主/单一第三方 | 单源，默认不可靠，必须标注身份（如"博主 X 实测"） |
| ⚪ 未经核实 | 无来源/纯推断/过期信息 | 一律单列"未核实清单"，不得混入结论正文 |

**升级要点**：
1. 标"已查证"≠"我搜到过"，必须官方一手原文可回源；
2. "经搜索补充"必须双源，1 源一律降"一方说法"；
3. 关键数字（价格/时长/积分/门槛）至少双源，否则降档。

## 3. 状态类结论专项检查（LibTV/Imagen 教训）

对工具/平台的**状态结论**（"有无 API""是否支持 X""价格"）必做：

1. 查"最近升级/下线/停更"信号：官方 changelog、官方公告端点、模型页"停止服务"标记（如 Imagen 下线、LibTV Skill→CLI）；
2. 官方 URL 逐条活链验证（旧入口 404 即失效信号，如 /zh/cli）；
3. 能下载的官方包（CLI/SDK/zip）下载解压核验，不只看 README 摘要；
4. 状态结论与静态 README 冲突时，以官方公告/产品页最新为准。

## 4. 多智能体协作流（4 调研 + 1 验证 + 1 主控）

```
主控 Organizer（分解任务→派发→收口→整合）
 ├─ 调研 SubAgent ×N（按主题分路，如 A 全景工具 / B1 叙事SOP / B2 故事平台 / C 数字人）
 │    每路交付：结论 + 证据等级 + 来源链接 + 未核实清单（四档标注强制）
 ├─ 验证 SubAgent ×1（独立于调研路，禁止与调研 Agent 共享来源偏好）
 │    抽查：随机抽 ≥30% 关键结论 + 全部"已查证"项
 │    回源：官方 URL 可达性、原文是否支持结论、双源独立性、等级是否虚标
 │    输出：验证报告（通过 / 打回 + 具体原因 + 补查要求）
 └─ 打回机制：验证未过 → 结论打回对应调研路补查 → 复验 → 通过后才允许整合入库
```

**协作规则**：
1. 验证 Agent 与调研 Agent **完全独立**（各自搜索、不回看对方过程）；
2. 主控整合时只收"验证通过"的结论；未过项以"未核实/一方说法"呈现或暂缺；
3. 调研路之间若结论冲突（如两路对同一工具口径不一），主控先交验证 Agent 仲裁再定稿；
4. 交付物三件套：调研底稿（证据链）+ 结论文档（整合）+ 验证报告（附件）。

## 5. 验证检查清单（验证 Agent 逐项执行）

1. **官方性**：每条"已查证"的 URL 直接可访问？原文内容支持该结论？（反例：README 支持 ≠ 官方公告支持）
2. **双源独立性**：每条"经搜索补充"≥2 来源？来源互不转载（同一转载链只算 1 源）？
3. **数字核验**：价格/时长/积分/认证门槛等关键数字双源一致，否则降"一方说法"
4. **状态时效**：工具是否升级/下线/改名？最近更新日期？官方 changelog 是否打脸结论？
5. **等级诚实度**：无来源推断是否落入"未经核实"？是否混入结论正文？
6. **链路完整性**：URL 是否完整可回源（不留"来源见上文"式模糊指针）？

## 6. 与现有机制的衔接

- 质量门禁 v2.0（G1–G5）管**产出物**（SOP/图/视频/音频）；本机制管**调研结论**（证据链），两者串联：调研结论 → 进 SOP → G1 检查；
- 调研底稿统一入 `09_调研底稿与素材/`（原始素材只读），整合结论入 `01_结论与产出/`；
- CHANGELOG 记录每次调研交付与验证结果。
