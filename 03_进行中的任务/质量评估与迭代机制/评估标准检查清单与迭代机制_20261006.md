# 珠宝AI视频SOP仓库 · 评估标准检查清单 v1.0 与迭代机制

> 用途：仓库内每份 SOP/底稿产出或大任务完成后，按本清单重跑质量评估，形成"评估→精炼→复查"的固定迭代循环。
> 版本：**v1.0**（2026-10-06）。v0 为纯标准推导草稿；v1.0 已用仓库 4 份真实文档（主SOP 470行/无模特版 88行/总纲 150行/douyin底稿 221行）**实测校准一轮**，并新增 6 条本轮发现的失败模式（标 🔧校准新增）。
> 评估四维固定：语言精炼（L）/ 结构合理（S）/ 专业性（P）/ 可执行性（E）。来源标注四档：已查证 / 经搜索补充 / 博主一方说法 / 未经核实。
> 判定规则：**通过条件列即失败阈值——命中即该项 ❌**。单维失败 ≥2 条 → 该维不通过；四维失败合计 ≥6 条 → 整份文档打回重写。单份文档（≤500 行）目标 10 分钟跑完。🤖=可脚本机械执行，👁=需人眼判断。

## 三、迭代机制说明（核心）

### 3.1 循环定义

```
产出或变更（新SOP / 改SOP / 大任务完成 / 季度巡检）
   ↓
① 评估：按本清单 38 项重跑（10 分钟/份，结果填标准结果表）
   ↓ 失败项 = 0？ ──是──→ ④ 归档（TASK_STATUS + CHANGELOG 记录）
   ↓ 否
② 精炼：按问题表逐项修改（内容错误 P0 优先）
   ↓
③ 复查：对改动文档**重跑同一清单**，确认失败项归零或显式豁免
   ↓ 通过
④ 归档：更新 TASK_STATUS / CHANGELOG / ISSUES（评估→精炼→复查 闭环完成）
```

### 3.2 触发时机（4 类）

| 编号 | 触发时机 | 必跑对象 | 说明 |
|---|---|---|---|
| T1 | **新 SOP / 新底稿定稿时** | 新文档 | 每次产出的默认关卡，不可跳过 |
| T2 | **大任务完成后**（新工具线/新流水线/方案图批次/大改版） | 受影响的全部文档 + 关联文档 | 防止只改一处、别处口径漂移（本轮 B/A 矛盾即此模式） |
| T3 | **季度巡检** | 全仓库 `01_结论与产出/` + `09_调研底稿与素材/` 所有 md | 覆盖低频文档与孤儿文件 |
| T4 | **跨文档矛盾被发现时** | 矛盾双方 | 立即触发，不等季度（本轮 P9 即此类） |

### 3.3 执行人

- 默认执行人：**主Agent**（每次迭代会话开始时先读本清单；可将机械项沉淀为脚本/复用 Skill）；
- 🤖 机械项：grep/wc/ls 即可，可脚本化批量跑；
- 👁 判断项（术语语境、套话定性、验收可判定性）：由人/主Agent 判定，**拿不准按"未核实"处理并记入 ISSUES**；
- 本轮（2026-10-06）已建立**基线**：评估报告 + 精炼方案 + 本清单，作为后续迭代的起点。

### 3.4 验收标准

1. 清单失败项 = 0；若有豁免，必须在结果表备注栏写明原因（如"09 只读，待授权"）；
2. 单维失败 ≥2 或四维合计 ≥6 → 打回重写（不是局部修补）；
3. 精炼后必须**重跑同一清单**复查，0 残留才允许归档；
4. 每次迭代产出两份记录：结果表（清单逐项）+ 变更记录（CHANGELOG）。

### 3.5 如何重跑（操作手册）

1. 打开本清单文档（`评估标准检查清单与迭代机制_20261006.md`）；
2. 阶段 0 机械扫描（2 分钟）：`wc -l` 看篇幅 → `grep -n "^#"` 看标题层级 → `head -10` 看元信息头 → 对引用路径跑 `ls` 验存在；
3. 阶段 1 套话与术语（2 分钟）：按 §四命令扫套话、同义术语；
4. 阶段 2 步骤精读（4 分钟）：从"操作步骤"节逐行读（一步一动作/参数全/有分支/有预期/有回退/人工点标注）；
5. 阶段 3 专业性核对（2 分钟）：每个事实结论查来源档；跨文档 grep 同一数字对比；术语首次出现查定义；合规硬墙查禁忌句；
6. 填结果表【编号 | ✅/❌ | 证据位置（行号）| 备注】，存至 03_进行中的任务/评估记录/ 目录（新建评估记录，文件名按"YYYYMMDD_文档名.md"命名规范）；
7. 按结果执行精炼或放行归档。

### 3.6 与仓库既有治理联动

- **问题登记**：评估失败项 → `03_进行中的任务/ISSUES.md` 登记，延续现有 ISSUE-001~008 编号体系（本轮可登记：ISSUE-009 无模特版术语违规、ISSUE-010 知识库指针、ISSUE-011 孤儿底稿…）；
- **进度**：每次迭代开始/完成更新 `TASK_STATUS.md`；
- **变更史**：精炼执行写入 `CHANGELOG.md`；ADR 只增不改；
- **只读约束**：09 目录文件的修正走精炼方案第六章选项（A 记 ISSUES / B 出修订版到 01 / C 用户豁免），清单本身不改变此约束。

### 3.7 迭代节奏建议

| 轮次 | 内容 | 状态 |
|---|---|---|
| 第 0 轮（本轮） | 建立基线：评估报告 + 精炼方案 + 清单 v1.0 + ISSUES 待办 | ✅ 已完成（基线文档见同目录） |
| 第 1 轮 | 执行精炼方案 P0–P3（不动 09）→ 复查归零 | ⬜ 待主Agent确认后执行 |
| 第 2 轮 | 拍板 09 处理选项 → 执行 P4 → 复查归零 | ⬜ 待决策 |
| 此后 | T1–T4 触发即跑，10 分钟/份，滚动迭代 | 常态化 |
